## 1. 레벨 고정 버그 (수정)

`조기 승급` 증강(경험치 요구량 −12)을 먹으면 **그 뒤로 레벨이 오르지 않았다.**

```ts
// xpToNextLevel: 3레벨에서 XP_TO_LEVEL[4] = 6, 6 - 12 → Math.max(0, -6) = 0
// addXp:        if (need <= 0 || player.xp < need) break;   ← 0이면 즉시 탈출
```

레벨 2~5의 요구 경험치(2 / 2 / 6 / 10)가 전부 할인 12보다 작아, 증강을 집은 시점의
레벨에 그대로 묶였다. 증강은 2-1에 제시되고 그때 대부분 3레벨이므로 **"3레벨에서 멈춘다"**
는 제보와 정확히 일치한다.

**수정**

- `xpToNextLevel`은 최소 **1**을 반환한다(최대 레벨에서만 0).
- `addXp`의 탈출 조건에서 `need <= 0`을 제거한다.

레벨업 비용이 0이 되는 경우가 사라지므로 어떤 할인 조합에서도 레벨이 멈추지 않는다.
`tests/economy.test.ts`가 전 레벨 구간을 검증한다.

## 5. 레이스 플랜 / GⅠ 출주 시스템

### 5.1 무엇인가

경주의 의사결정 구조를 오토배틀러에 옮긴 시즌 메커니즘이다.

| 시점 | 단계 | 귀속 |
|---|---|---|
| 2-5 | **출주 계획** — 기본 플랜 3장 | 없음 |
| 3-5 | **전개 수정** — 진화 3장 | 없음 |
| 4-5 | **GⅠ 출주 등록** — 승부마 1명 지정 | 유닛 |
| 등록 직후 | **최종 승부수** — 3장 | 그 유닛 |

- 증강 라운드(2-1 / 3-2 / 4-2), 회전 드래프트(x-4), PvE(x-7)와 겹치지 않는다.
- 골드·경험치·상점 확률을 일절 건드리지 않는다. 그 영역은 증강체의 정체성이다.
- 체력 20 이하인 플레이어는 **4-3에 조기 개방**된다. 파워는 동일하고 접근권만 앞당긴다.

### 5.2 콘텐츠 물량

기본 플랜 **24** · 진화 **24** · 범용 승부수 **26** · 고유 승부수 **16** = **90 노드**
GⅠ 테마 **30종**(UmaRogue `race-templates.json`의 GI/JpnI 전체)

### 5.3 레이스 진행도 — 이 시스템의 핵심

`docs/BALANCE.md` 실측에서 오버타임 진입은 17.4%다. 즉 **전투의 80% 이상이 30초 전에
끝난다.** "25초에 발동" 같은 효과는 대부분 존재하지 않는 글자가 된다.

그래서 페이즈를 시계가 아니라 **레이스 진행도**로 자른다. 경마에서도 최종 직선은
경과 시간이 아니라 남은 거리로 정해진다.

```
진행도 = max(
  경과 시간 / 30초,
  가장 몰린 쪽의 기물 소모율,
  가장 몰린 쪽의 체력 소모율
)
```

- **전체 필드가 아니라 한쪽 진영** 기준이다. 양쪽을 합치면 8:0 완승도 0.5에 그쳐
  최종 직선에 영영 닿지 않는다.
- **체력 소모율을 함께 본다.** 3레벨 보드는 기물이 3명뿐이라 1명 사망이 1/3인 반면,
  상대 캐리가 체력 15%로 버티는 상황은 누가 봐도 마지막 직선이다.
  기물 수만 보면 8명 미만 보드에서 최종 직선이 나오지 않았다.
- 진행도는 **되돌아가지 않는다.** 부활·소환이 1회성 보상을 재생시키면 안 된다.

| 페이즈 | 진행도 | 시계 환산 |
|---|---|---|
| 템 START | 0 – 0.17 | 0–5초 |
| 도중 POSITIONING | 0.17 – 0.67 | 5–20초 |
| 승부처 LATE | 0.67 – 0.83 | 20–25초 |
| 라스트 3F | 0.83 – 1.0 | 25–30초 |
| 극한 승부 OVERTIME | 시계 30초 초과 | 기존 규칙 |

`tests/race-plan.test.ts`가 실제 매치 시뮬레이션에서 **PvP 전투의 80% 이상이 라스트 3F에
도달**하는 것을 검증한다.

### 5.4 역할 가드

모든 노드가 `MELEE / RANGED / ANY`를 선언하고, 승부수 단계에서는 **하드 필터**로 쓴다.
TFT 이상현상 `눈알 광선`이 원거리 챔피언에게 가면 광선이 닿지 않는 것과 같은 사고를 막는다.

가드를 전부 통과하는 **범용 8종**이 5개 카테고리를 덮으므로, 로스터 145명 누구에게도
항상 서로 다른 카테고리 3장을 줄 수 있다. 전수 검사로 강제한다.

실제 사례: **사일런스 스즈카는 각질이 도주지만 이 게임에서는 사거리 4의 `AP_CARRY`다.**
고유 승부수에 이동속도를 넣으면 이동하지 않는 유닛에게 이동 버프를 주는 꼴이므로,
공격속도와 `독주` 상태로만 표현했다.

### 5.5 적성은 퍼센타일로 가중한다

실측: **잔디 A 이상이 145명 중 132명(91%)**, **더트 F가 93명.**
등급 문자를 그대로 가중치로 쓰면 잔디는 거의 전원에게 보너스를 주고 아무것도 구분하지 못한다.

그래서 `horse-racing-profiles.json`에 **로스터 내 퍼센타일(`*Pct`)** 을 함께 생성하고,
가중치는 이것만 본다. 등급 문자는 UI 표기 전용이다. 최대 ±15%이며 어떤 등급도 후보를
삭제하지 않는다.

### 5.6 데이터

  하드코딩되어 `PREP_SECONDS.AUGMENT`(45)와 어긋나던 것**도 함께 고쳤다.

## 7. 후속 — AI 인지, 플레이어 도움말, 설명 문장 (2026-09-13 2차)

### 7.1 AI가 자기 작전을 알게 했다

기존에는 `resolveAiRacePlans`가 카드만 골랐고, **보드 운영은 레이스 플랜을 전혀 몰랐다.**
`src/game/engine/ai/`에 race-plan 참조가 0건이었다. 그 결과 AI가 자기 GⅠ 출주마를
벤치에 두거나 팔아버리는 일이 실제로 일어났다.

40매치 실측(등록 이후 1,911 라운드 표본):

| 현상 | 이전 | 이후 |
|---|---:|---:|
| 출주마가 필드에 없음(작전 전부 비활성) | 2.1% | **0.0%** |
| 판매·소멸로 분리됨 | 0.6% | **0.0%** |

- `chooseFieldedUnits`: 선발 후 등록된 출주마를 가장 약한 선발 기물과 교체해 **반드시 출전**시킨다.
  선발 캐시 키에 `entryUnitDefId`를 넣어 등록이 바뀌면 캐시가 무효화된다.
- `sellSurplus`: 출주마와 같은 `unitDefId`는 판매 후보에서 제외한다. 여분 사본도 그 말의 성 합성이다.
- `itemFit`: 출주마에게 장비 가산점(+4), 여기에 현재 플랜·전개·승부수가 원하는 축
  (`fit.itemAxes`)과 맞는 장비면 축당 +2. 작전을 고른 말에게 장비가 모인다.

AI가 실제로 고른 서로 다른 플랜 19 / 24종, 서로 다른 승부수 19종으로 한두 개에 수렴하지 않는다.

### 7.3 설명 문장

**줄바꿈** — `.effect-sentence { display: block }`이 마침표마다 줄을 끊어 두 문장짜리 설명을
문단 더미로 만들고 있었다. `display: inline`으로 바꿔 문장이 자연스럽게 이어진다.

**문체** — 스킬 설명 42종을 명사 나열형에서 자연스러운 문장으로 다시 썼다.
수치·동작·`+N%` 토큰은 한 글자도 바꾸지 않았다(`+N%`는 빌더가 코스트별로 재계산하므로 형식이 유지되어야 한다).

```
이전  돌진 후 직선 6칸의 최대 4명에게 방어력 20% 감소(4초)와 381 물리 피해.
이후  안쪽으로 파고들며 직선 6칸의 최대 4명을 제칩니다.
      4초 동안 방어력이 20% 무너지고 381의 물리 피해를 입습니다.
```

**서명 재스탬프** — 설명은 순수 UI 텍스트이고, 리뷰 테스트의 `motionContract` 자체가
비교 전에 `description`을 지운다. 즉 문구 수정은 그림을 무효화하지 않는다.
`scripts/restamp-style-correction.mjs --copy`가 커밋된 빌드와 대조해
**`description` 외에 달라진 필드가 하나라도 있으면 거부**하고, 통과할 때만 서명을 다시 찍는다.
현재 스킬을 가리키지 않는 QA 기록(`adaptive-balance-motion-compatibility`,
`augment-motion-compatibility`, `cost-skill-compatibility`)은 각자의 의미에 맞게
따로 갱신한다 — 과거 스냅샷의 문구는 건드리지 않는다.

## 8.1 각질 페이즈 보정 — 이 패치의 중심

`src/game/engine/race-plan/style-curve.ts`

도주와 추입이 첫 1초부터 마지막 1초까지 똑같은 힘으로 싸우고 있었다. 경마가 절대 하지
않는 한 가지다. **모든 유닛**이 — GⅠ 출주마만이 아니라 — 각질에 따른 구간별 곡선을 탄다.

| 구간 | 도주 | 선행 | 선입 | 추입 |
|---|---:|---:|---:|---:|
| 발주 | **+12%** / 방어 +2% | +5% / +1% | −5% / **방어 +6%** | **−9%** / **방어 +10%** |
| 중반 | +7% | +7% / +1% | +1% / 방어 +3% | −3% / 방어 +7% |
| 4코너 | 0% | +9% | +12% | +14% |
| 최종 직선 | **−8%** / 방어 +6% | +5% | **+18%** | **+26%** |

두 가지가 이걸 "그냥 상쇄되는 숫자"에서 구해낸다.

1. **시간이 대칭이 아니다.** 중반이 경주의 절반이고 4코너·최종 직선은 각각 6분의 1이다.
   그래서 후반형은 프리미엄을 받고 전반형이 내놓는 대가는 실제보다 작다.
2. **생존이 곡선의 절반이다.** 중반에 죽은 추입은 아무것도 못 받는다. 선입·추입은 후반
   화력을 **초반 피해감소로 산다.** 이게 거래를 실제 선택으로 만든다.

구간 길이로 가중한 총합은 넷이 0.055 / 0.073 / 0.072 / 0.088로 좁은 밴드 안에 있고,
`tests/race-plan.test.ts`가 이 폭을 0.06 미만으로 강제한다.

## 8.8 부수 수정 — 출주마 추천

`entryFit`에서 아이템이 사실상 세어지지 않고 있었다. `unitItemFit(unit, undefined)`가

- 축이 없으면 "얼마나 갖춰졌는가"로 폴백한다
- 캐리 강도를 보드 최강 후보 대비 상대값으로 읽는다 — 절대값은 후보들 사이에서 압축돼
  적성 가중이 뒤집기에 충분할 만큼 좁았다
- 적성 0.10→0.07, 시그니처 0.05→0.03. 문서가 "10%는 의도된 장식"이라고 말하는 대로
  실제로 장식이 되게 한다
