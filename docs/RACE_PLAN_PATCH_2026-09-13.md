## 1. 레벨 고정 버그 (수정)

`조기 승급` 증강(경험치 요구량 −12)을 먹으면 **그 뒤로 레벨이 오르지 않았다.**

```ts
// xpToNextLevel: 3레벨에서 XP_TO_LEVEL[4] = 6, 6 - 12 → Math.max(0, -6) = 0
// addXp:        if (need <= 0 || player.xp < need) break;   ← 0이면 즉시 탈출
```

레벨 2~5의 요구 경험치(2 / 2 / 6 / 10)가 전부 할인 12보다 작아, 증강을 집은 시점의
레벨에 그대로 묶였다. 증강은 2-1에 제시되고 그때 대부분 3레벨이므로 **"3레벨에서 멈춘다"**
는 제보와 정확히 일치한다.

**수정**

- `xpToNextLevel`은 최소 **1**을 반환한다(최대 레벨에서만 0).
- `addXp`의 탈출 조건에서 `need <= 0`을 제거한다.

레벨업 비용이 0이 되는 경우가 사라지므로 어떤 할인 조합에서도 레벨이 멈추지 않는다.
`tests/economy.test.ts`가 전 레벨 구간을 검증한다.

## 4. 4·5코스트 밸류덱 조정

`COST_SKILL_POWER`와 `starSkillMultiplier`는 `SkillDef.baseValues` /
`SkillDef.starMultipliers`에 그대로 들어가고, **145명 전원의 아트 리뷰가 그 해시를 고정**한다.

## 5. 레이스 플랜 / GⅠ 출주 시스템

### 5.1 무엇인가

경주의 의사결정 구조를 오토배틀러에 옮긴 시즌 메커니즘이다.

| 시점 | 단계 | 귀속 |
|---|---|---|
| 2-5 | **출주 계획** — 기본 플랜 3장 | 없음 |
| 3-5 | **전개 수정** — 진화 3장 | 없음 |
| 4-5 | **GⅠ 출주 등록** — 승부마 1명 지정 | 유닛 |
| 등록 직후 | **최종 승부수** — 3장 | 그 유닛 |

- 증강 라운드(2-1 / 3-2 / 4-2), 회전 드래프트(x-4), PvE(x-7)와 겹치지 않는다.
- 골드·경험치·상점 확률을 일절 건드리지 않는다. 그 영역은 증강체의 정체성이다.
- 체력 20 이하인 플레이어는 **4-3에 조기 개방**된다. 파워는 동일하고 접근권만 앞당긴다.

### 5.2 콘텐츠 물량

기본 플랜 **24** · 진화 **24** · 범용 승부수 **26** · 고유 승부수 **16** = **90 노드**
GⅠ 테마 **30종**(UmaRogue `race-templates.json`의 GI/JpnI 전체)

### 5.3 레이스 진행도 — 이 시스템의 핵심

`docs/BALANCE.md` 실측에서 오버타임 진입은 17.4%다. 즉 **전투의 80% 이상이 30초 전에
끝난다.** "25초에 발동" 같은 효과는 대부분 존재하지 않는 글자가 된다.

그래서 페이즈를 시계가 아니라 **레이스 진행도**로 자른다. 경마에서도 최종 직선은
경과 시간이 아니라 남은 거리로 정해진다.

```
진행도 = max(
  경과 시간 / 30초,
  가장 몰린 쪽의 기물 소모율,
  가장 몰린 쪽의 체력 소모율
)
```

- **전체 필드가 아니라 한쪽 진영** 기준이다. 양쪽을 합치면 8:0 완승도 0.5에 그쳐
  최종 직선에 영영 닿지 않는다.
- **체력 소모율을 함께 본다.** 3레벨 보드는 기물이 3명뿐이라 1명 사망이 1/3인 반면,
  상대 캐리가 체력 15%로 버티는 상황은 누가 봐도 마지막 직선이다.
  기물 수만 보면 8명 미만 보드에서 최종 직선이 나오지 않았다.
- 진행도는 **되돌아가지 않는다.** 부활·소환이 1회성 보상을 재생시키면 안 된다.

| 페이즈 | 진행도 | 시계 환산 |
|---|---|---|
| 템 START | 0 – 0.17 | 0–5초 |
| 도중 POSITIONING | 0.17 – 0.67 | 5–20초 |
| 승부처 LATE | 0.67 – 0.83 | 20–25초 |
| 라스트 3F | 0.83 – 1.0 | 25–30초 |
| 극한 승부 OVERTIME | 시계 30초 초과 | 기존 규칙 |

`tests/race-plan.test.ts`가 실제 매치 시뮬레이션에서 **PvP 전투의 80% 이상이 라스트 3F에
도달**하는 것을 검증한다.

### 5.4 역할 가드

모든 노드가 `MELEE / RANGED / ANY`를 선언하고, 승부수 단계에서는 **하드 필터**로 쓴다.
TFT 이상현상 `눈알 광선`이 원거리 챔피언에게 가면 광선이 닿지 않는 것과 같은 사고를 막는다.

가드를 전부 통과하는 **범용 8종**이 5개 카테고리를 덮으므로, 로스터 145명 누구에게도
항상 서로 다른 카테고리 3장을 줄 수 있다. 전수 검사로 강제한다.

실제 사례: **사일런스 스즈카는 각질이 도주지만 이 게임에서는 사거리 4의 `AP_CARRY`다.**
고유 승부수에 이동속도를 넣으면 이동하지 않는 유닛에게 이동 버프를 주는 꼴이므로,
공격속도와 `독주` 상태로만 표현했다.

### 5.5 적성은 퍼센타일로 가중한다

실측: **잔디 A 이상이 145명 중 132명(91%)**, **더트 F가 93명.**
등급 문자를 그대로 가중치로 쓰면 잔디는 거의 전원에게 보너스를 주고 아무것도 구분하지 못한다.

그래서 `horse-racing-profiles.json`에 **로스터 내 퍼센타일(`*Pct`)** 을 함께 생성하고,
가중치는 이것만 본다. 등급 문자는 UI 표기 전용이다. 최대 ±15%이며 어떤 등급도 후보를
삭제하지 않는다.

### 5.6 데이터

- `race-templates.json` / `racecourses.json`을 `sync:data`에 추가했다.
- 프로필 생성은 **기존 `build-game-data.ts`에 단계로 붙였다.** 별도 임포트 스크립트는 없다.
  `horse-game-db.json`은 이미 vendor되어 있고 `aptitudes` / `affinities`를 전부 포함한다.
- `horseId` 조인은 **145/145 정확 일치**다. 실패하면 빌드를 세운다.
- `ROSTER_HASH`에 넣지 않는다. 넣으면 기존 세이브와 방 체크포인트가 전부 무효가 된다.
- 커버리지 리포트: `docs/generated/RACE_PLAN_DATA_IMPORT_REPORT.md` (자동 생성)

### 5.7 멀티플레이

- 신규 메시지 타입 없음. `commandSchema`에 `action` 6종만 추가했다.
- **`privateMatch()`가 상대의 현재 오퍼·추천 근거·최근 전투 프로파일을 제거한다.**
  스카우팅에는 플랜 / 진화 / 출주마 / 승부수만 노출된다.
- `setDeadline()`에 레이스 플랜 분기를 추가했다. 같은 수정에서 **증강 대기시간이 30초로
  하드코딩되어 `PREP_SECONDS.AUGMENT`(45)와 어긋나던 것**도 함께 고쳤다.
- 타임아웃 자동 선택은 `options[0]`이 아니라 **추천 1위**를 집는다. 세 칸은 순위가 아니라
  역할(A 강점 / B 다른 전개 / C 경마적 선택)이기 때문이다.

### 5.8 세이브 호환

`GAME_VERSION`·`SAVE_KEY`·`ROSTER_HASH` 모두 그대로다. `PlayerState.racePlan`은 optional이고
로드 시 백필한다. 이번 패치는 로스터 데이터가 바뀌므로 `ROSTER_HASH`가 달라져 기존 세이브는
어차피 무효지만, **레이스 플랜 자체는 세이브를 깨지 않는다.**
