## 1. 물리 피해가 빈약했던 진짜 이유

총량은 문제가 아니었다. 측정하면 AD 캐리가 **35.7%**로 전 역할 중 가장 많은 피해를
넣고 있었다. 문제는 **빌드 경로**였다.

```ts
// 수정 전 — 피해 속성과 무관하게 항상 주문력을 읽었다
amount *= source.skillMultiplier * skillAbilityPowerMultiplier(stat(source, 'abilityPower'));
```

모든 유닛의 주문력 기본값은 **100으로 고정**이고 스킬 피해는 오직 거기에만 스케일했다.
결과:

| | 평타 | 스킬 |
|---|---|---|
| **공격력 아이템** | 오른다 | **아무 영향 없음** |
| **주문력 아이템** | — | 오른다 |

스킬이 전체 피해의 **43%**를 차지하므로, AD 아이템은 출력의 절반만 올리고 AP 아이템은
전부를 올렸다. 로스터의 authored 피해 효과 **32개가 PHYSICAL**인데 그중 어느 것도
공격력으로 키울 수 없었다.

### 수정

물리 캐스팅은 **시전자 자신의 기준선 대비 공격력**으로 스케일한다. 주문력이 authored
100 대비로 읽히는 것과 정확히 같은 의미다.

```ts
amount *= source.skillMultiplier * (type === 'PHYSICAL'
  ? skillAttackDamageMultiplier(stat(source, 'attackDamage'), source.base.attackDamage)
  : skillAbilityPowerMultiplier(stat(source, 'abilityPower')));
```

기준선은 상수가 아니라 **그 유닛의 시작 공격력**이다. 주문력과 달리 공격력은 코스트와
별에 따라 이미 달라지기 때문이다. 기본 상태에서는 1배가 나오므로 아이템·특성·버프가
움직이기 전에는 아무것도 바뀌지 않는다 — 주문력 경로와 같은 성질이다.

`tests/skill-star-scaling.test.ts`가 두 경로의 대칭을 고정한다.

## 2. 브루저가 파고들지 못했던 이유

**8명의 브루저 전원이 이미 스킬에 `DASH`를 갖고 있었다.** 문제는 목표였다.

```ts
// 타겟팅은 모든 역할이 동일하게 "가장 가까운 적"
foes.sort((a, b) => hexDistance(unit.cell, a.cell) - hexDistance(unit.cell, b.cell) || ...);
// 그리고 DASH 는 현재 타겟으로 돌진한다
case 'DASH': { const t = opts.currentTarget ?? ...; ctx.dash(self, t, ...); }
```

가장 가까운 적은 항상 최전열 탱커다. 즉 **브루저는 이미 붙어 있는 탱커에게 돌진**하고
있었다. 역할에 동작만 있고 일이 없었다.

### 수정 — 무방비 캐리

브루저는 **전투 시작 시점에 옆에 아군 몸이 없던** 캐리를 노린다.

```ts
private markExposedCarries(): void {
  const guards = this.units.filter((u) => u.role === 'TANK' || u.role === 'BRUISER');
  for (const unit of this.units) {
    if (!['AD_CARRY', 'AP_CARRY', 'SUPPORT'].includes(unit.role)) continue;
    const screened = guards.some((g) => g.team === unit.team && hexDistance(g.cell, unit.cell) <= 1);
    if (!screened) this.exposedAtStart.add(unit.id);
  }
}
```

그리고 `DASH`도 같은 목표를 쓴다. 기존 8개 스킬이 **새 그림 없이** 돌입기가 됐다.

### 판정을 전투 시작 시점에 고정한 이유

처음에는 매 틱 실시간으로 판정했다. **작동하지 않았다** — 최전열은 접촉과 동시에
전진하므로 1~2초 뒤에는 모든 스크린이 풀리고 어떻게 배치했든 전 캐리가 무방비가 된다.
플레이어가 실제로 내리는 결정은 **배치**이므로, 판정도 배치를 본다.

### 측정

같은 8유닛, 배치만 다르게:

| 수비측 배치 | 브루저 피해 중 캐리에게 |
|---|---:|
| 캐리 옆에 몸 있음 | **38%** |
| 캐리 혼자 노출 | **72%** |

`tests/bruiser-dive.test.ts`가 이 격차를 고정한다. 반격 수단이 실제로 존재해야 하고,
아니면 이건 위치 메커니즘이 아니라 그냥 버프다.

전체 집계로는 브루저의 피해 비중이 **17.8% → 20.7%**로 올랐다.

## 3. 원거리 AD딜러 — 사거리는 건드리지 않았다

현재 시즌1 배치:

| 역할 | 사거리 | 수 |
|---|---:|---:|
| AD_CARRY | 3 (추입 2) | 15 |
| AP_CARRY | **4** | 9 |

AD 캐리가 같이 후열에 서야 할 AP 캐리보다 **한 칸 앞에** 선다. 원딜 역할에 자기 자리가
없다는 지적은 정확하다.

**그래서 AD 캐리를 4로 올려 봤고, 되돌렸다.**

| 변형 | 4코 도배덱 vs 리롤덱 |
|---|---:|
| 현행 (AD 3 / AP 4) | 기준 |
| AD **4** / AP 4 | **90%** |
| AD **4** / AP **3** (완전 교체) | **99%** |

4코 티어는 **11명 중 캐리 8명**이다. 캐리를 겨냥한 버프는 무엇이든 *약해야 마땅한 보드
형태*에 가장 크게 떨어진다. 사거리는 원딜 정체성을 주는 대신 4코 도배덱을 지배적으로
만들었고, 그건 바로 직전 패치에서 고치려던 문제다.

원딜 정체성은 **하는 일**로 만드는 게 맞다 — 위 §1의 물리 스케일링이 그 첫 걸음이고,
공격속도·치명타로 지속 딜을 내는 쪽과 큰 한 방을 쓰는 쪽의 구분은 이미 존재한다.
사거리 변경은 로스터의 역할 분포(4·5코에 앞줄이 2·3명뿐)가 정리되기 전까지는 넣지 않는다.

## 4. 계측 도구의 버그 — 발견하고 고침

`scripts/audit-cost-curve.ts`가 **캐리를 탱커 앞에 세우고 있었다.**

```
board r=0 → A팀 cell r=4 / B팀 cell r=3   ← 두 팀이 맞닿는 경계
board r=3 → A팀 cell r=7 / B팀 cell r=0   ← 가장 뒤
```

`r=3`을 최전열로 착각했다. 양쪽 모두 같은 방식이라 비교 자체는 성립했지만, **아무도
만들지 않는 보드**를 재던 것이라 밴드가 전부 잘못 잡혀 있었다.

고친 뒤 지표를 재설계했다. **앞줄을 양쪽 동일하게 고정하고 뒷줄만 바꾸는** 행을 추가해
코스트/별 곡선 자체를 재고, 전체 덱 비교는 따로 둔다.

| 지표 | 값 | 밴드 |
|---|---:|---|
| [앞줄 고정] 고코 1성 캐리 vs 3코 2성 캐리 | 68.7% | 40–70 |
| [앞줄 고정] 고코 2성 캐리 vs 3코 2성 캐리 | 100.0% | 65–100 |
| [앞줄 고정] 고코 1성 캐리 vs 3성 섞인 캐리 | 6.0% | 0–35 |
| 밸류덱 vs 리롤덱 **[미해결]** | **0.0%** | 20–50 |
| 밸류덱(2성 캐리) vs 리롤덱 | 94.0% | 55–95 |
| 4코 도배덱 vs 리롤덱 | 1.3% | 0–40 |

앞줄을 고정하면 **1성 고코 캐리가 2성 3코 캐리를 68.7%로 이긴다** — 지난 패치에서 잡은
"N코 1성 ≈ (N−1)코 2성" 관계가 올바른 배치에서도 성립한다는 확인이다.

## 5. 밸류덱 vs 리롤덱 0% — 이 수치는 한 조건에서만 잰 것이다

> **2026-09-14 정정.** 아래 0%는 `audit:cost-curve`가 재는 **단 하나의 조건**에서 나온
> 값이다 — 아이템 없음, 증강 없음, 레이스 플랜 없음, 배치 한 가지. 그 조건에서 일반화한
> "밸류덱은 리롤덱을 못 이긴다"는 결론은 근거가 부족했다. 전 조건 스윕 결과는
> `npm run audit:matrix`와 [MATCHUP_MATRIX_2026-09-14.md](MATCHUP_MATRIX_2026-09-14.md)를 볼 것.

그 조건에서의 원인 분석은 유효하다 — 캐리가 아니라 **앞줄**이다.

| | 밸류덱 앞줄 | 리롤덱 앞줄 |
|---|---|---|
| 1코 탱커 | 2성 **1170** | 3성 **2106** |

리롤덱은 사본 9장을 앞줄에 박아 넣는다. 밸류덱은 그럴 수 없다 — **4·5코 티어의 앞줄
유닛이 각각 2명, 3명뿐**이라 값싼 탱커를 쓸 수밖에 없고, 값싼 탱커 싸움은 리롤한 쪽이
이긴다.

이건 코스트 곡선으로 고칠 수 없다. **비싼 티어에 앞줄 유닛이 필요**하고, 그건 로스터
결정이다. `audit:cost-curve`에 `[미해결]`로 표시해 매 실행마다 숫자가 보이게 두었고,
게이트에서는 제외해 CI를 막지 않는다.
