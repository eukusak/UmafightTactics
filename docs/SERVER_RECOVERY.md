# 온라인 방 서버 재시작 복구

## 구현 범위

`ROOM_STATE_FILE`을 지정하면 Node 서버가 2초마다 방 체크포인트를 저장하고 시작할 때 복원한다. SIGTERM/SIGINT에도 마지막 저장을 시도하고 WebSocket 연결을 종료한다. 환경변수를 생략하면 기존 메모리 방식이다.

- 대기실 8개 좌석·방장·준비 여부·좌석 토큰·마지막 명령 번호 보존.
- 상점·벤치·공유 풀·난수 상태·증강·드래프트 보존.
- 전투는 재시뮬레이션하지 않는다. 기록과 미정산 결과를 보존하므로 전투 중 구매도 유지된다.
- 복원 시 모든 소켓을 연결 해제 상태로 만들며, 기존 브라우저의 방 코드와 좌석 토큰으로 재접속한다.
- 중단된 서버 시간만큼 준비/선택/전투 마감 시각을 이동한다. 재개 후에는 기존 공통 시계가 계속 흐르며, 연결 없는 방은 기존 5분 만료 규칙을 따른다.
- 복원 후에도 각 좌석에 현재 재생 시각까지의 기록만 전송한다. 정산은 한 번만 실행한다.

## 실행

Linux 예시:

```sh
ROOM_STATE_FILE=/var/data/umafight/rooms.json npm start
```

Windows PowerShell 예시:

```powershell
$env:ROOM_STATE_FILE = 'C:\UmafightData\rooms.json'
npm start
```

Render에서는 Node Web Service에 영구 디스크를 연결하고 마운트 경로 아래 파일을 환경변수에 지정해야 한다. 기존 `render.yaml`은 디스크 구매나 배포 설정을 자동 변경하지 않는다. 임시 파일시스템에 저장하면 배포 교체 시 보존되지 않을 수 있다. 외부 서비스 배포/영구 디스크 연결은 이번 변경으로 수행되지 않았다.

## 파일 처리와 제한

체크포인트에는 좌석 자격 증명, 상대 상점, 아직 공개되지 않은 전투 결과가 들어 있으므로 Git이나 공개 웹 경로에 올리지 않는다. 서버는 `public`/`dist` 안의 설정 경로를 거부한다. 새 파일 권한은 0600, 새 부모 디렉터리는 0700이다. 임시 파일에 쓰고 fsync 후 rename으로 교체한다. 손상된 JSON, 버전/로스터 불일치 등 복원 오류 시 서버 시작을 중단해 기존 파일을 빈 상태로 덮어쓰지 않는다.

단일 프로세스 전용이다. 여러 프로세스가 같은 파일을 동시에 쓰면 안 된다. 서버 강제 종료 시 마지막 성공 저장 이후 최대 약 2초의 진행이 되돌아갈 수 있으며, 저장 실패가 지속되면 그 이상 손실될 수 있다. 운영 환경의 파일시스템/정전 내구성, WAN 부하 및 여러 서버 동기화는 검증하지 않았다. 로스터 외 전투 규칙을 바꾸는 배포는 체크포인트 호환성 검토가 필요하다.

## 검증

- 8명 대기실/드래프트 저장·복원·좌석별 재접속 및 개인정보 분리.
- 전투 0.5초 시점 저장 → 서버 90초 중단 가정 → 기록/남은 시간 복원.
- 전투 중 명령 번호·상점 잠금 보존, 미래 기록 비전송.
- 재시작 없는 진행과 정산 결과/다음 라운드 상태/난수 상태 일치.
- 이미 정산한 결과 중복 지급 방지.
- 파일 실제 쓰기/읽기/교체·권한·최초 실행·손상 파일 보존.
- 실제 로컬 Node 프로세스 SIGTERM → 저장 → 프로세스 재시작 → WebSocket 좌석 재접속 성공.
- 전체 143개 테스트, 타입 검사, 린트 통과. 코드 프로덕션 빌드 통과(로컬 검증 환경은 기존 바이너리 아트 미다운로드로 배경 경로 경고 발생; 원격 아트 파일은 변경하지 않음).

실제 외부 서버를 재배포하는 검증이나 추가 브라우저 화면 검수는 이번 변경에 포함하지 않았다. 아트 수량은 기존 222/514개이며, 실제 Cubism 리깅과 나머지 아트 제작은 별도 미완료 상태다.
