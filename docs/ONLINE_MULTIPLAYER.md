# 온라인 8인 방 대전

## 실행

```bash
npm ci
npm run build
npm start
```

기본 HTTP 포트 4173, `PORT`/`HOST` 변경 가능. `/health`는 상태 검사, `/multiplayer`는 WebSocket 업그레이드 경로다. 개발 서버 `npm run dev`에도 같은 룸 서버가 붙는다. 기존 `node scripts/serve.mjs`도 같은 온라인 서버를 실행한다. 정적 `vite preview`와 `npm run start:static`에는 룸 서버가 없다.

메인 메뉴의 온라인 대전에서 이름을 입력하고 방을 만든다. 6자리 코드를 공유하고 8명이 준비하면 방장이 시작한다. 방장은 AI 좌석을 추가·제거할 수 있다. 빈자리 AI 옵션을 체크하면 방장 1명 + AI 7명으로도 시작할 수 있다. 모든 사람 참가자가 준비해야 시작하며 AI는 자동 준비된다. 상대의 준비/접속 상태를 로비에서 확인할 수 있다.

## 권위와 연결

- 경제·공유 풀·조합·배치·장비·증강·드래프트·매칭·피해·순위는 서버가 결정한다. 클라이언트는 명령만 전송하며 금액/승패/프레임을 쓰지 못한다.
- 좌석 토큰은 24바이트 암호학적 난수로 만들고 해당 브라우저 탭의 sessionStorage에 저장한다. 원래 탭의 새로고침 후 온라인 메뉴에서 이전 방 재접속을 누른다. 일시 연결 끊김은 자동 재시도한다. 토큰은 다른 사용자에게 전달하지 않는다.
- 재접속 시 본인 상태와 현재 시각까지의 전투 이력을 복구한다. 동일 좌석의 이전 연결은 종료한다. 상대 상점/벤치/아이템 보관함, RNG/풀 잔량은 숨긴다. 상대 배치와 장착 아이템은 정찰할 수 있다.
- 준비/드래프트/증강 선택 시간은 서버 기준이다. 미선택 드래프트·증강은 제한 시간 뒤 자동 선택하고 부족한 출전 인원은 보유 대기석에서 채운다. 전투는 1배속이며 개인 건너뛰기/일시정지로 서버를 멈출 수 없다.
- 공통 전투 종료 후 HP·보상·탈락을 한 번 정산하고 결과 5초 후 다음 라운드로 이동한다. 연결이 끊긴 좌석도 시간은 계속 흐른다.
- 초당 메시지 40개, 메시지 8KiB, 연결 128개, 방 16개 한도. 허용 Origin 확인, heartbeat, 느린 수신자 재접속 처리가 있다. 다른 프런트 도메인은 `ALLOWED_ORIGINS`에 정확한 origin을 쉼표로 구분해 지정한다.

## 배포 범위와 남은 운영 기능

`render.yaml`은 단일 Node Web Service 설정으로 변경했다. 기존 Render Static Site는 이 파일 수정만으로 Node 서비스로 바뀌지 않으므로 Node Web Service로 새로 구성해야 한다. 외부 서비스 생성/배포는 이 PR에서 수행하지 않았다.

현재 방은 단일 프로세스 메모리 기반이다. 모든 좌석이 오프라인인 방은 5분 후 삭제하며, 프로세스 재시작 시 진행 중 방은 사라진다. 수평 확장, 내구성 있는 경기 저장, 계정 로그인/랭크 매칭, 지역별 지연 시험과 대규모 부하 검증은 아직 없다. 나가기는 연결 종료이며 즉시 항복 처리하지 않는다. 남은 좌석은 보유 편성으로 자동 진행한다.

검증은 실제 WebSocket 8개와 Chromium 독립 컨텍스트 8개의 로컬 통합 시험이다. 외부 WAN 8인 서비스의 지연/가용성 검증까지 완료했다는 뜻은 아니다.


## 서버 재시작 복구 (후속 반영)

`ROOM_STATE_FILE`을 지정하면 방과 진행 중 전투를 저장·복원할 수 있습니다. 미설정 시 기존 메모리 방식입니다. 영구 디스크 설정, 복구 동작 및 제한은 [SERVER_RECOVERY.md](SERVER_RECOVERY.md)를 참조하세요. 외부 배포는 아직 수행하지 않았습니다.
