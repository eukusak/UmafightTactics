# 2026-09-07 아트 방향 및 구현 상태

사용자의 최신 지시가 기존 `ART_REQUEST.md`의 도트 스타일보다 우선한다.
목표는 TFT의 판타지 아레나와 우마무스메의 경마 학원 분위기, 현대 포켓몬 게임을 연상시키는 매끈한 셀 셰이딩이다. 남색·청록 패널, 금색 주요 행동, 따뜻한 아이보리 글자, 입체적인 테두리와 부드러운 그림자를 사용한다. 기존 발주서의 파일명, 셀 크기, 행·열, 앵커, 프레임 수는 유지한다.

현재 구현은 React + Phaser의 **2D 렌더링에 원근감과 애니메이션을 적용한 2.5D 표현**이다. 실제 3D 모델이나 Live2D Cubism 리깅은 포함하지 않는다.

규격 통과는 파일 크기·PNG·알파 채널 검사를 뜻하며 모든 자산의 런타임 사용을 뜻하지 않는다. 아이콘은 상점/아이템/특성/증강에 연결했다. 스킬 VFX는 CAST 이벤트에 연결했다. 별 등급 VFX는 합성 완료 알림에 연결했고, 전투 기록의 상태 아이콘도 연결했다. UI 아틀라스와 일부 배너·능력치 상태 아이콘은 아직 모두 연결된 것은 아니다.

`STRICT_ART=1` 검수는 누락 294건(P0 126 / P1 168)으로 실패해야 정상이다. 일반 검수의 성공을 전체 납품 완료로 해석하지 않는다.

## 화면과 전투

- 타이틀, 메인 메뉴, 도감, 상점, 벤치, HUD, 특성/아이템 패널, 드래프트, 증강 선택, 결과 화면의 색·타이포·계층·프레임을 변경했다. 한글 폰트를 앱에 포함했다.
- 준비 보드와 전투 보드는 같은 원근 좌표를 사용한다. 배치한 앞열/뒷열이 전투 진입 때 뒤집히지 않는다.
- 전투 객체를 재사용하고 기록된 프레임 사이의 위치를 보간한다. 공격/스킬/피격/사망/부활/승리 상태를 기록 이벤트에서 재생한다. 피해 수치는 실제 ATTACK 피해량을 사용한다.
- 배속 변경은 전투를 처음부터 재시작하지 않는다. 피해량 표시 설정을 적용한다.
- PvE는 훈련장, PvP는 스테이지에 따라 주간/야간/더트 배경을 사용한다. 이는 장식이며 지형 효과나 특성 판정을 바꾸지 않는다.
- 캐릭터 시트가 없으면 참고 썸네일을 사용한다. 썸네일의 상하 이동은 최종 캐릭터 애니메이션을 대체하지 않는다.

## 캐릭터 제작 및 잘라 쓰기

`docs/art-source/character-production-plan.json`에 145명의 정확한 ID, 참고 Race 파일, 스킬 템플릿, 스킬명, 키 포즈 지시, VFX, P0/P1 우선순위를 기록했다. 동일한 스킬 템플릿의 키 포즈 지시는 공유하며, 캐릭터별 최종 원화/세부 동작 검토는 아직 필요하다. `samson_big`, `genuine`의 참고 파일은 2026-09-08 사용자 첨부로 보충되어 전체 145명 매칭을 완료했다.

스페셜 위크 시트의 내장 생성/투명화 재시도는 RGB 체크무늬 배경과 잘못된 포즈 개수를 반환했다. 첫 실패 샘플은 `docs/art-source/special_week_rejected_rgb.png`에 남겼다. 이를 RGBA로 형식만 바꾸거나 빈 프레임을 복제해 납품하지 않았다.

실제 투명 10×6 시트를 검토한 뒤 다음과 같이 가져온다.

```bash
python3 -m pip install -r requirements-art.txt
python3 scripts/slice-character-sheet.py special_week /absolute/reviewed-sheet.png
python3 scripts/build-system-art.py
```

출력은 `public/assets/characters/<unitId>.png`와 `public/assets/characters/frames/<unitId>/<clip>/00.png`, `animation.json`이다. 프레임마다 원래 셀 좌표를 유지하여 흔들림을 방지한다. 128×128 셀, 앵커 (64,110), idle 6 / run 8 / basic_attack 8 / skill_cast 10 / hit 4 / ko 6 / victory 8의 총 50프레임이다. 실제 포즈의 자연스러움과 앵커 정렬은 별도 육안 검수가 필요하다.

가져오기는 RGB, 불투명 배경, 잘못된 격자, 비어 있는 필수 프레임, 여백 셀의 그림, 셀 경계에 닿는 그림을 거부한다. 기존 납품 폴더를 덮어쓰지 않는다. 초상화/컷인은 별도 발주 규격에 맞춰 제작해야 한다.

## 재생성과 검증

- `scripts/build-system-art.py`: 시스템 아이콘, VFX, UI, PvE 생성 및 전달 자산 목록 갱신. 벡터 아이콘 원본은 `public/assets/system_vectors/`에 있다.
- `scripts/build-reference-previews.py`: Race 이미지의 정면 얼굴 썸네일 143개를 재생성한다. 출처 SHA와 미리보기 상태를 별도 목록에 기록하며 최종 납품으로 세지 않는다.
- `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`로 코드 검증.
- `node --import tsx scripts/check-art-manifest.ts`는 `npm run check:art`와 동일한 검수 코드다. 현재 실행 환경의 tsx CLI IPC 제한 때문에 이 호출법을 사용했다.
- Chromium 1440×810 및 1366×768에서 타이틀→메뉴→매치 생성→드래프트→배치→전투→4배속→결과를 실행하고 콘솔 오류 0건을 확인했다. 1366×768 도감에서도 깨진 이미지 0건을 확인했다. 캡처는 `docs/screenshots/`에 있다. 기존 114개 테스트와 신규 재생 계약 테스트 3개가 통과했다.

배경 생성은 내장 이미지 도구를 사용했으며 API/CLI 대체 생성은 사용하지 않았다. 배경의 공통 프롬프트와 장면별 지시는 `art-source/background-prompts.md`에 정리했다.

## 2026-09-08 이어서 적용한 내용

- 합성으로 실제 별 등급이 상승할 때 2성/3성/5코 3성 효과를 구분해 12프레임으로 재생하고, 캐릭터명과 별 등급을 2.2초간 표시한다. 최초 화면 진입이나 유닛 이동을 합성으로 처리하지 않는다.
- 전투 기록에 있는 8종 상태를 머리 위 최대 4열×2행으로 표시한다. 중복은 제거하고 상태 해제/사망을 반영한다. 전용 이미지가 없는 무장 해제는 한글로 표시한다.
- HP/마나 게이지 표시 범위를 0~100%로 제한했다.
- 타입 검사, 린트, 전체 117개 테스트 및 프로덕션 빌드 통과. Chromium 1366×768에서 합성 알림, 모든 상태를 주입한 표시 검수, 전투→4배속→결과→도감 경로를 확인했다. 콘솔 오류 및 깨진 도감 이미지 0건. 상태 주입은 검수 브라우저 메모리에만 적용했고 게임 데이터에 저장하지 않았다.
- 스페셜 위크 재생성은 내장 image_gen으로 Race 참고 이미지와 투명 1280×768, 10열×6행, 50동작을 요청했다. 반환 파일은 RGB 1619×972이며 체크무늬 배경, 부족한 동작 수, 격자 경계 문제를 확인했다. 최종 자산으로 가져오지 않았다. 따라서 납품 수량은 216/514 그대로이며 캐릭터 자산 298개는 여전히 미완료다.

캐릭터 재시도 프롬프트 요약: SpecialWeek-Race.png 정체성·승부복 유지; 현대 포켓몬풍의 부드러운 셀 셰이딩 2.5D 3등신; 우측 3/4 전신; 실제 알파 투명; 1280×768, 128px 셀 10×6; 발 앵커(64,110); idle6/run8/attack8/dash10/hit4/ko6/victory8; 남은 셀 완전 비움; 각 셀 10px 여백; 그림자·배경·격자·텍스트 금지. API/CLI 방식은 사용하지 않았다.

## 2026-09-08 두 참고 파일 보충 이후

현재 정본은 위 납품 표이며 이전 날짜/시점의 수량은 당시 이력이다.

- 사용자 제공 Genuine.png / SamsonBig.png를 이름에 맞춰 race 폴더에 보존하고 출처·SHA·검토한 썸네일 영역을 manifest에 기록했다. 참고 이미지와 썸네일은 145명 모두 연결된다.
- 내장 이미지 생성으로 제뉴인, 삼손 빅, 스페셜 위크, 토카이 테이오의 실제 투명 RGBA 전신을 제작했다. `docs/art-source/standees`에 원본, `public/assets/characters/standees`에 512×512 전신, `public/assets/portraits`에 256×256 초상화가 있다. 배경을 코드로 제거하거나 RGB를 RGBA로 형식만 변환하지 않았다. 원래 알파를 유지해 잘라 크기를 맞췄다.
- 전신의 발 앵커는 (256,440)으로 통일했다. 준비/전투에서 같은 크기와 발 위치를 쓴다. 전신 4개는 추가 런타임 자산이며 **원래 50동작 시트 납품 수량으로 세지 않는다**. 초상화 4개만 기존 표에 추가한다.
- 전투 중 WebGL 메시의 17개 제어점을 이용해 발을 고정한 상태로 상체의 호흡·이동·공격·피격을 변형한다. Canvas 환경에서는 동일 전신 이미지의 회전/크기 변형으로 표시한다. 이는 Live2D 느낌의 절차적 표현이며 Cubism 리깅이나 독립적으로 그린 보행/공격 원화 50장이 아니다.
- 하루 우라라·오구리 캡은 전신 생성 및 배경 제거 재시도에도 RGB 체크무늬가 남아 적용하지 않았다. 전체 캐릭터 제작과 145×50프레임은 완료되지 않았다.
- 준비/전투는 하나의 영구 배경과 SVG 육각 격자를 공유한다. Phaser는 투명 캔버스로 유닛과 효과만 표시하며 로드 중에는 준비 유닛을 유지한다. 필드 배치 유닛은 instance ID로 유지하고 280ms 위치 전환을 적용했다.
- 이동은 목적지 예약→이동률 증가→도착 정리로 변경했다. 이전 칸으로 보간이 되돌아가던 문제를 없앴다. 공격은 준비 동작→발사→명중으로 분리하며 일반 공격·스킬·보호막 피해 모두 실제 DAMAGE 기록에서 피격/숫자를 표시한다. 준비 중 기절·무장 해제, 대상 사망/대상불가 조건을 처리한다.
- 준비 타이머와 시간 만료 시 자동 전투, 빈 출전 슬롯 자동 배치를 연결했다. 선택 화면 중에는 타이머가 멈추며 싱글플레이 편의를 위한 일시정지 버튼이 있다. 전투 시작 중복 호출을 막았다.
- 합성 효과의 6열×2행 규격을 실제 재생 코드에 반영했다.

검증: 전체 121개 테스트 통과(기존 117개 + 명중 시점/이동 연속성/무장 해제/첫 훈련 회귀 4개), 타입 검사·린트·빌드 통과. 새 전신 4명의 배치·이동·전투·배속·결과 화면 및 도감 검수에서 콘솔 오류/깨진 이미지 0건. 캡처는 `screenshots/standee-prep.png`, `screenshots/standee-battle.png`다. 테스트 화면은 4명을 함께 확인하기 위해 브라우저 메모리에 검수용 편성을 넣었으며 게임 데이터는 변경하지 않았다.

TFT 대조 범위와 아직 동일하지 않은 항목은 [시스템 연동 기록](TFT_INTEGRATION_2026.md)에 명시한다. 이번 공격/이동 타이밍 변경은 전투 결과에 영향을 줄 수 있으며 캐릭터 기본 스탯과 경제 수치는 기존 명세를 유지한다.

초반 훈련 보정: 실제 자동 출전 검수에서 첫 PvE 패배를 확인해 1스테이지 PvE HP·AD 배율을 0.35로 낮췄다. 2스테이지 이후는 유지한다. 모든 1코스트 시작 유닛에 대해 무장비 3개 시드에서 첫 훈련 승리를 검사했다. 준비 타이머 만료 후 자동 출전 및 중복 없는 1회 전투 시작도 브라우저에서 확인했다.
